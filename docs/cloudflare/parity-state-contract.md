# Document state and realtime parity

The app exposes the unchanged Go API and bridge protocol:

- `GET /v1/documents/:id/kv`: viewer; `{revision,items}` snapshot.
- `PATCH /v1/documents/:id/kv`: editor; `{set,delete}` patch and `{revision,changes,updated_by}` result. Null means delete, explicit delete wins, sets and deletes are sorted independently. Empty patches retain the revision. Key names use ASCII letters, digits, `.`, `_`, `:`, `-`, at most 128 bytes; value 64 KiB; body 256 KiB; at most 256 changes.
- `GET /v1/documents/:id/kv/events`: viewer; SSE revision IDs. KV messages remain unnamed; document, comments, presence messages have their kind as the SSE event name. Resume uses the greater of `after_revision` and `Last-Event-ID`. Omitting both starts at the live edge.
- `POST /v1/documents/:id/presence`: viewer; 4 KiB body, session 8–64 ASCII letters/digits/underscore/hyphen, version at most 64 bytes, quote 512 Unicode code points and context 64 each. Identity and picture come from the authenticated principal. DOM paths and caller-supplied leave flags are ignored.

Undo and redo remain bridge-local history operations: read current items, verify history, apply the inverse/forward PATCH. No server undo endpoint is introduced.

D1 stores existing `document_kv` and `document_revisions`, plus migration `0003_state.sql`'s `document_events(document_id,revision,kind,event_json,updated_at)`. The `(document_id,revision)` primary key is the persisted event sequence shared by KV, document changes, comments and presence. State and its event commit in the same D1 batch. A SQL authorization guard in that transaction prevents queued mutations from publishing after an editor grant is revoked.

`DOCUMENT_REALTIME` is a Durable Object namespace bound to `DocumentRealtime`, configured with `new_sqlite_classes`. Every state read/write, announcement and subscriber registration routes to `idFromName(documentID)`. The object serializes D1 state operations, then publishes committed events to its SSE subscribers. Internal `/announce` calls are reachable only through the binding; mutation services call `announceDocumentEvent(env,actor,id,kind)` after document/comment writes.

SSE subscribers revalidate the exact server-authenticated credential and current viewer permission before live delivery, consumer pulls and the 25-second keepalive. One `json_each` query evaluates all subscribers for a producer, including revoked CLI/service keys, disabled service accounts, session expiry/logout, inherited grants and current deployment group snapshots. Connections close after confirmed revocation. Temporary D1 failures pause delivery and retain the persisted backlog for retry, without sending unverifiable updates or treating resource failures as revocation. Presence snapshots omit SSE IDs; presence replay older than 45 seconds is filtered. A stream carrying a session emits a leave event when its server-side stream closes. The implementation also installs stream-cancel and request-abort cleanup hooks.

SQLite-backed Durable Objects are [available on Workers Free](https://developers.cloudflare.com/durable-objects/platform/limits/). Long-running SSE keeps an object active and consumes the Free plan's [duration allowance](https://developers.cloudflare.com/durable-objects/platform/pricing/), currently 13,000 GB-seconds/day and 100,000 requests/day. Streams and timers prevent [hibernation](https://developers.cloudflare.com/durable-objects/concepts/durable-object-lifecycle/). This deployment requires no paid subscription; quota exhaustion fails requests rather than granting unlimited free usage. The existing SSE wire protocol is retained.

The realtime tests bundle the production Durable Object into Miniflare/workerd with SQLite storage and real D1. They verify concurrent revision allocation, inverse patches, normalized validation, persisted replay, presence identity, live SSE, viewer denial and revocation.

## Bounded delivery and disconnect cleanup

Like Go's live broker, each subscriber buffers at most 32 live events and disconnects on overflow. A reconnect resumes from the client's last delivered SSE ID. The producer enqueues only when the consumer requests a chunk, using a zero high-water mark. Replay, current presence, and persisted live gaps load at most one 32-row D1 page per pump invocation. Pages containing only expired presence yield to another private invocation, so skipped events cannot exhaust a request budget. The response is returned before history is read. Replay registration captures the current revision under Durable Object serialization; new live events enter the bounded queue while replay is consumed. Gap pages and revision cursors prevent missed or duplicate IDs, including gaps left by expired presence removal. Historical KV, document and comment events are retained.

Authorization is checked before each live publication, each replay/presence/gap page and each keepalive. Replay batches database queries across 32 events instead of querying once per event, preserving the Workers Free request budget for ordinary replays. Consumer pulls dispatch private `/resume` invocations, so each authorization and bounded replay page uses a fresh request budget. Free-plan D1 limits still apply to each invocation and total usage.

Production Cloudflare and local workerd probes confirmed that remote HTTP cancellation does not reliably invoke the Durable Object producer's cancellation hook. The implementation retains abort/cancel hooks and also records the timestamp of consumer pull demand. A 25-second heartbeat closes the subscriber once demand has been inactive for more than 45 seconds, clears its timer and buffers, and records its session's presence leave. This is the explicit Cloudflare adaptation for abandoned streams; an actively reading idle client continues requesting heartbeats and stays connected. Inactivity is observed on the heartbeat tick, so cleanup can take up to 70 seconds. No lease forces an active client to reconnect.

Actual D1/workerd regression tests verify the 32-event queue under 64 unread large patches, overflow closure and resumed IDs, more than 100 large replay events without full-history prefetch, a persisted gap longer than one replay page, expired presence filtering, revocation, and an idle native consumer's leave after 55 seconds. Paging and idle-consumer assertions use a test-only reader inside the workerd actor; host HTTP readers can prefetch or delay cancellation through Undici buffers. Explicit native cancellation has its own persisted-leave test. Other tests still use the HTTP transport for framing, replay, revocation and overflow. Test-only subclass instrumentation observes queue lengths and replay page counts without adding production diagnostic endpoints.

Producer authorization uses one bound JSON actor array and a shared document-role SQL expression. The ordinary predicates retain their two actor-ID bindings. Google Group grants require a fresh snapshot for the enabled current deployment customer. A subscriber needing a stale membership refresh pauses delivery while the refresh runs through a separate internal Durable Object invocation for that principal. Pending readers resume through separate invocations after refresh, outside the producer's query budget; self-calls are never awaited while holding `blockConcurrencyWhile`. Batched disconnect presence leaves also use bounded D1 statements, with earlier leave revisions replayed as persisted gaps.

Runtime regression tests inject a 50-statement limit into real D1/workerd request execution and verify delivery to 16 and 64 distinct CLI users, selective and mass revocation with session leaves, exact session expiry/logout, revoked service keys, disabled accounts, fresh and refreshed inherited group denial, and transient authorization failure followed by exact persisted replay. Consumer pull work has its own test request budget, so it cannot mask producer fanout costs.

Heartbeat timers dispatch private `/heartbeat` requests by subscription key instead of querying D1 in the stream-opening request context. Each tick revalidates the exact credential and current access, pumps a bounded page if requested, and emits the unchanged keepalive. At most one heartbeat invocation per subscriber is outstanding. Inactivity cleanup runs in that fresh invocation; abort/cancel hooks dispatch private `/close` requests for presence cleanup. These binding-only calls are scheduled without awaiting a self-call under Durable Object serialization. Temporary authorization failures pause the tick and are retried by a later fresh invocation.

Accelerated actual workerd regressions retain the opening invocation's cumulative D1 statement counter, enforce a 50-statement ceiling, and consume 120 heartbeats without exhaustion. They verify heartbeat-only credential revocation, stale inherited group refresh and denial, persisted backlog retry after transient authorization failure, and inactivity presence leaves using an aged demand timestamp. A 1,200-row expired presence replay verifies bounded continuation without consuming the original invocation budget. Production heartbeat and inactivity thresholds remain 25 and 45 seconds.
