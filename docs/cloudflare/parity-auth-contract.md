# Identity and MCP parity contract

Canonical behavior is `api/internal/auth/{oidc,oidc_settings,mcp}.go`, `api/internal/server/handlers_{auth,service_accounts}.go`, and the MCP tool/authorization modules.

The Cloudflare schema keeps `users` as backing storage for all individual principals because existing actor foreign keys target it. Service account backing rows have `provider='service_account'`, their own ID as subject, an empty email, and the bot address as name. They must be excluded from human lookup/login/search and never authenticate through browser sessions or CLI credentials. Public DTOs identify them as `service_account`, including owners, authors, reactions, and grants. `service_accounts`, `service_account_keys`, and `ownership_transfers` hold native metadata. Disablement and key revocation reject future requests and realtime heartbeats.

OIDC uses one configured provider. Both `/v1/auth/google/{start,callback}` and `/v1/auth/oidc/{start,callback}` are aliases. Configure the complete `SLASHDOCS_OIDC_{ISSUER_URL,CLIENT_ID,CLIENT_SECRET}` family, optional `INTERNAL_ISSUER_URL` and `PROVIDER_NAME`, or the Google legacy client ID/secret pair. Mixing families fails closed. Discovery validates the public issuer; split-horizon discovery, token exchange, and JWKS use the internal base, while browser authorization uses the public base. Signature, audience, issuer, expiry, subject, email and OAuth nonce are verified. Missing `email_verified` is accepted; explicit false is rejected, matching upstream. Generic identity IDs hash the versioned issuer-plus-subject namespace, preventing cross-provider collisions. Placeholder transfer recipients bind to their first verified login without changing their ID.

Service account routes: POST/GET `/v1/service-accounts`, PATCH `/:id`, POST/GET `/:id/keys`, DELETE `/:id/keys/:key_id`, POST `/:id/transfer`, GET `/v1/service-accounts/transfers`, POST `/transfers/:id/{accept,decline}`. Creation accepts `{label,domain?}` and returns `{id,label,name,owner:{id,email},disabled,grants:[],key:{id,token}}`; new keys return `{id,token}` once, listed keys contain only `{id,name}`. Account listing/patch returns `{id,name,owner:{type:'user',id,email,name},disabled}`. Transfers return `{id,service_account_id,from_user_id,to_user_id,status}`. Only owners manage accounts and keys. Only recipients accept; either party can decline. Acceptance atomically changes ownership and pending status. Transfer creation can create a placeholder recipient.

MCP transport is stateless, JSON-only Streamable HTTP `/mcp`. It requires a bearer on every request and rejects cookies, CLI credentials, cross-origin requests, and invalid credentials. Native `slashdocs_sa_` and legacy `aidocs_sa_` keys authenticate bots; short-lived `slashdocs_mcp_` tokens authenticate humans with resource audience `mcp:<APP_ORIGIN>/mcp`. Methods include initialize, ping, tools/list, tools/call and initialized notifications. Domain mutations delegate canonical HTTP handlers rather than implement a second permissions path. Tool annotations preserve read-only, destructive and idempotent flags. Successful JSON results return text plus structured content; HTTP errors become `isError` tool results.

OAuth routes: GET `/.well-known/oauth-protected-resource`, GET `/.well-known/oauth-protected-resource/mcp`, GET `/.well-known/oauth-authorization-server`, POST `/oauth/register`, authenticated GET/POST `/oauth/authorize`, POST `/oauth/token`. Public dynamic registrations accept 1–10 HTTPS/loopback/private-use-app redirects, no credentials/fragments, only token auth `none`, authorization_code with optional requested refresh_token and response `code`. The server issues no refresh tokens; advertised grants remain authorization_code. Consent checks registered redirect, resource, scope mcp and PKCE S256. Codes are single-use and bound to client, redirect, resource, challenge and user. Access tokens expire in one hour. Registration lifetime is one year. OAuth errors use `{error,error_description}`.

Tests use real Miniflare D1 and signed provider tokens; only external discovery/token/JWKS fetches are mocked. No live credentials or admission-policy files are required.
